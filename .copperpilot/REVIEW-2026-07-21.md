# Design Review — LattePanda Mu Carrier Board

Date: 2026-07-21 | KiCad 10.0.3 | Board: 170.1 x 100.0 mm, 4-layer

## Method
- Ran `kicad-cli sch erc` and `kicad-cli pcb drc` (client-side).
- Inspected netlist connectivity for U14 (CH224K USB-PD), U6 (RTL8111H GbE PHY).
- Cross-referenced against README block map (9 sub-sheets).

## ERC Results: 0 errors, 36 warnings
All warnings are cosmetic, not connectivity bugs:
- 20x `lib_symbol_mismatch` / `lib_symbol_issues` — symbols edited locally diverge from library copies, and `A_HDJ_Library` path still points to the original author's absolute `/Volumes/T7/...` path (broken on this machine but harmless since KiCad falls back to the project-local `Libraries/` copy via `${KIPRJMOD}`... verify `sym-lib-table` uses the relative path, not the absolute one baked into individual symbol metadata).
- 16x `multiple_net_names` in `usb_2_3.kicad_sch` — hierarchical labels (`USB_2_P2-`) and local labels (`CON_USB3_D_N`) are tied to the same wire. Not an error, but confusing; KiCad silently prefers one name. Recommend removing the redundant label on each net for clarity.

## DRC Results: 4 errors, 18 warnings
| Severity | Issue | Where |
|---|---|---|
| Error x4 | Courtyard overlaps between LattePanda Mu module (A1) and H5, H6 (mounting holes) and R78/R79 | Module footprint overlaps nearby mounting-hole and resistor courtyards |
| Warning | Silkscreen clipped by board edge | J18 (USB-C), J17 (DC jack), J6 |
| Warning | Silkscreen clipped by solder mask / overlap | A1 GND pad silkscreen, J17 pads, UART label vs rectangle |
| Warning | Footprint differs from library copy | U14, SW1/SW2, J17, A1 — same root cause as ERC symbol mismatches, now at footprint level |

**Priority fix:** the 4 courtyard-overlap errors around the LattePanda Mu module edge connector — confirm mechanical clearance is real or a false positive from an oversized courtyard on the module footprint; either way this should be resolved before fab to avoid assembly/probe issues near H5/H6/R78/R79.

## Connectivity Spot-Checks
- **U14 (CH224K USB-PD controller):** VBUS, CC1/CC2, D+/D- all wired to Type-C connector correctly. `CFG2`, `CFG3` (pads 2/3) and `PG` (pad 10) are unconnected. CFG pins select the negotiated voltage profile via strapping — confirm this floating condition matches the CH224K datasheet's intended default config (open = specific voltage set); if a fixed PD voltage is required, these need pull resistors.
- **U6 (RTL8111H GbE PHY):** Power (+1V0, +3V3), GND, and MDI0-3 differential pairs to the magnetics look correctly wired. `CLKREQB` (pad 12) and `LED0` (pad 27) are unconnected — both optional (PCIe clock request and status LED), not required for basic link-up but worth confirming against your GbE_PCIe_CLK usage on the PCIe sheet, since RTL8111H shares a PCIe reference clock with the PCIe x4 slot.
- Net analysis shows differential pairs are named consistently across sheets (`GbE_PCIe_CLK+/-`, `MDI0+/-` etc.) — hierarchical labeling is clean.

## What's Done Well
- Zero ERC errors and zero DRC unconnected-item errors — full netlist connectivity is intact across all 9 sub-sheets.
- Consistent hierarchical net naming for high-speed diff pairs (Ethernet MDI, PCIe clock, USB3 SS lanes).
- 4-layer stackup with internal power planes (In1.Cu/In2.Cu) appropriate for this rail count (+12V/+15V/+1V0/+3V3/+5V/+BATT).
- Power path protection ICs (D3V3XA4B10LP, multiple instances) placed on each I/O rail — good ESD/surge practice for connectors.
